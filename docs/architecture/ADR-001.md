# ADR 001 FitFlow Cross Platform Architecture

## Status

Accepted

## Context

FitFlow requires mobile and web applications, personalized workout recommendations, camera-based nutrition logging, private community features, progress tracking, notifications and offline support.

The architecture must also support the interface improvements identified during the Lab 4 usability evaluation.

## Decision

The FitFlow redesign will use:

- React Native and Expo for the mobile application
- React Native Web for the web application
- Node.js and Express for the backend API
- Firebase Firestore for application and real-time data
- Firebase Authentication for user registration and login
- Socket.IO for real-time communication
- TensorFlow Lite and ML Kit for suitable on-device AI
- An optional FastAPI service for advanced cloud AI
- GitHub Actions for basic continuous integration

## Rationale

This stack follows the technology direction described in the FitFlow case study. It supports rapid cross-platform development, real-time community features, offline use and on-device AI.

It can also support the AI-First Dashboard selected in Lab 3 and the usability improvements identified in Lab 4.

## Positive Consequences

- High code reuse across mobile and web
- Faster development
- Real-time and offline support
- Easy Firebase integration
- Practical support for on-device AI
- Lower initial development and maintenance cost

## Negative Consequences

- Express requires the team to maintain a clear backend structure
- Firestore is less suitable for complex relational queries
- Cloud AI processing introduces additional security and privacy responsibilities

## Alternatives Considered

Flutter was considered as a frontend alternative. NestJS was considered for a more structured backend. PostgreSQL was considered for complex relational data. These technologies may be reconsidered if the system becomes larger.
